# Viaduct

</div>

One command that converts a Google Chrome extension for Safari or Firefox.

viaduct is a thin front end over two engines. It picks one with `--browser` and
passes everything else straight through:

- Safari: [aqueduct](https://github.com/magicelk235/Aqueduct) rewrites the
  extension for Safari, then builds and signs it with Xcode.
- Firefox: [lavaduct](https://github.com/magicelk235/Lavaduct) rewrites the
  extension for Firefox.

Viaduct is also a Mac app that does this without a terminal:
[magicelklabs.com/viaduct](https://magicelklabs.com/viaduct/).

## Install

```sh
npm install -g @magicelk235/viaduct
```

## Usage

```sh
viaduct <inputs> [--browser safari|firefox] [engine options]
```

```sh
viaduct "Dark Reader.zip"                     # Safari
viaduct "Dark Reader.zip" --browser firefox   # Firefox
```

Without `--browser`, viaduct converts for Safari, exactly as viaduct 1.x did.
Every option other than `--browser` goes to the engine, so the option lists live
in the engines' READMEs: [aqueduct](https://github.com/magicelk235/Aqueduct#readme)
for Safari and [lavaduct](https://github.com/magicelk235/Lavaduct#readme) for
Firefox. `viaduct --help` shows the chosen engine's help (add `--browser firefox`
for Firefox's), and `--version` prints the engine's version.

## Requirements

- Safari: macOS, Xcode, and Node.js 18 or newer.
- Firefox: Node.js 22.13 or newer, on macOS, Windows or Linux.

## Upgrading from 1.x

Nothing changes for Safari. The inputs, flags and output are the same as
viaduct 1.18.0, because aqueduct is that code under a new name.

## Docs

The wiki is at
[github.com/magicelk235/Aqueduct/wiki](https://github.com/magicelk235/Aqueduct/wiki).
It documents aqueduct, which viaduct runs for Safari.

## Releasing

Viaduct.app downloads the npm `latest` tag and never downgrades, so a bad
`latest` can only be fixed by publishing a newer version. Every release goes to
`next` first and is promoted to `latest` once it has converted in the app.

1. To bump an engine, change its exact pin in `devDependencies` and run
   `npm install`.
2. Bump `version` in `package.json`: patch for an engine patch, minor for an
   engine minor or a new option, major for anything that changes Safari output.
3. Run `npm test`, commit and push the bump, then tag `v<version>` and create
   the GitHub release as a pre-release. The publish workflow sends a
   pre-release to the `next` dist-tag.

   ```sh
   npm test
   git commit -am "<version>" && git push
   git tag v<version> && git push origin v<version>
   gh release create v<version> --title v<version> --notes-file notes.md --prerelease
   ```

4. Quit Viaduct.app, install `next` into its CLI folder the way the app's
   updater does, and convert one extension in the app:

   ```sh
   CLI="$HOME/Library/Application Support/Viaduct/cli"
   W=$(mktemp -d) && (cd "$W" && npm pack @magicelk235/viaduct@<version>)
   tar xzf "$W"/magicelk235-viaduct-<version>.tgz -C "$W"
   rm -rf "$CLI" && mkdir -p "$CLI"
   cp -R "$W/package/dist" "$CLI/dist" && cp "$W/package/package.json" "$CLI/package.json"
   printf '<version>' > "$CLI/version.txt"
   ```

5. Promote it:

   ```sh
   npm dist-tag add @magicelk235/viaduct@<version> latest
   gh release edit v<version> --prerelease=false --latest
   ```
